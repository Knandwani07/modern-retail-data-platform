# 🪣 Amazon S3 Data Lake Structure

This project uses Amazon S3 as the central data lake for storing raw, processed, and query-result data. Organizing data into dedicated zones helps maintain a clean, scalable, and easy-to-manage data architecture.

## 📂 Bucket Structure

```text
retail-analytics-data-lake-pipeline-2026/
├── raw/
│   ├── customers/
│   ├── products/
│   └── orders/
├── curated/
└── athena-results/
```

---

## 📁 Folder Purpose

### raw/

Stores the original source datasets exactly as they are received before any transformation takes place.

#### customers/
Contains customer data files uploaded to the data lake.

#### products/
Contains product catalog files, including JSON datasets used for Snowflake processing.

#### orders/
Contains transactional order data used by AWS Glue ETL jobs.

---

### curated/

Stores transformed and cleansed datasets generated by AWS Glue ETL jobs.

Data in this layer is optimized for analytics, reporting, and downstream consumption by services such as Amazon Athena and Snowflake.

---

### athena-results/

Stores query results generated by Amazon Athena.

Each time an Athena query is executed, the results are automatically saved in this location for auditing and future reference.

---

## 🎯 Why This Structure Is Important

- Separates raw and processed data for better data governance.
- Simplifies ETL workflows and data management.
- Improves query performance by using curated datasets.
- Supports scalable analytics with Athena and Snowflake.
- Follows modern data lake architecture best practices.
- Makes troubleshooting and maintenance easier as the platform grows.

This folder structure serves as the foundation of the retail analytics platform and enables efficient data ingestion, transformation, governance, and reporting workflows.
